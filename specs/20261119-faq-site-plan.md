## 実装手順

1. `site/faq-data.js` を作成する。
   * `window.FAQ_DATA = [{ id, name, items: [{ q, a }] }, ...]` の形式。カテゴリ順・質問順は `qa.md` に一致させる（一般5、使い方8、高度な機能2、トラブルシューティング2）。
   * `a` は信頼できる固定の HTML 文字列（`<p>`、`<ul><li>`、`<strong>`、`<code>`）。質問 `q` はプレーンテキスト。
   * 製品名・コード表記は原文のまま、それ以外を日本語に翻訳する。
2. `site/index.html` を作成する。
   * ヘッダー（タイトル・サブテキスト）、検索 `input`（`label` 付き）、カテゴリタブ用コンテナ、件数表示（`aria-live="polite"`）、一覧コンテナ、空状態要素（初期は非表示）、フッター。
3. `site/style.css` を作成する。
   * 配色: 背景 #ffffff / #f4f4f4、本文 #262626、アクセント #0f62fe。
   * 最大幅 約800px、中央寄せ。システム日本語フォントスタック。
   * `:focus-visible` のアウトライン、タブの選択状態、アコーディオンの開閉インジケーター。
   * 幅 320px 以上で横スクロールなし。タブは折り返し。
4. `site/app.js` を作成する。
   * 起動時にカテゴリタブ（「すべて」＋4カテゴリ）を生成し、一覧を描画する。
   * 状態: `query`（文字列）、`category`（`all` または id）。
   * 検索: 前後空白除去、小文字化、空白区切り AND。対象は質問文と回答の HTML を除いたテキスト（描画時は `textContent` 相当で抽出）。
   * 描画: 条件に一致する Q&A のみカテゴリごとに描画。0件カテゴリの見出しは出さない。0件全体では一覧を隠し空状態を表示。
   * アコーディオン: `button`＋`aria-expanded`＋`aria-controls`、回答領域は `hidden` 属性で切替。複数同時展開可。
   * ユーザー入力は `textContent` / DOM API 経由でのみ扱い、HTML として挿入しない。回答 HTML は `faq-data.js` の固定データのみ `innerHTML` に挿入する。
5. 検証（後述）を実施し、不具合があれば修正する。

## GUI実装

* 対象コンポーネント: `site/index.html` の各セクション（ヘッダー、検索、タブ、件数、一覧、空状態、フッター）。一覧のカテゴリ見出しとアコーディオン項目は `app.js` が動的に生成する。
* スタイル: `site/style.css`（CSS のみ、外部依存なし）。
* 状態管理: `app.js` 内のモジュールスコープ変数（`query`、`category`）。変更時に `render()` を呼び再描画する（再描画時は全項目を閉じた状態に戻す）。
* 画面遷移: なし（単一ページ）。
* レスポンシブ対応: 最大幅 800px の中央寄せ、狭い画面ではパディング縮小とタブの折り返し。幅 320px / 768px / 1280px で確認する。

1. `grep -c '^### ' qa.md`（17）と、`faq-data.js` の Q&A 件数（node で `window` をスタブして読み込み、カテゴリ別件数 5/8/2/2 と合計 17）を照合する。
2. `node --check site/app.js site/faq-data.js` で構文を確認する。
3. 可能であればヘッドレスブラウザ等で `file://` 表示と主要操作を確認する。利用できない場合は静的確認にとどめ、実ブラウザでの目視確認項目（初期表示、開閉、検索、併用、0件、キーボード、320/768/1280px 幅）を未確認事項として報告し、ユーザーに確認を依頼する。
4. `git status` で変更が `site/` と `specs/` のみ、`qa.md` が未変更であることを確認する。
5. 仕様書の完了条件と照合する。
